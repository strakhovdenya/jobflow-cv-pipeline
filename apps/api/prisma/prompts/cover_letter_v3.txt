=== EVIDENCE SOURCE RULES ===

**Identify each knowledge source by its `sourceType`, never by its file name.** Every source block in `=== KNOWLEDGE SOURCES ===` opens with a header of the form `[Source: <sourceType> | <filePath>]`. The `sourceType` tells you the source's role; the file name changes whenever a source is revised and carries no meaning of its own. Use each source for its designated role:
- `profile_summary` — positioning guide.
- `cv_rules` — structure rules and the mapping of AI-related vacancy requests to evidence.
- `career_cases` — evidence bank for concrete cases and safe wording.
- `tech_stack` — guardrail against overclaiming; the candidate's real level and commercial/personal status per technology.
- `project_inventory` — map of career cases and personal projects.

The letter may state only what the approved targeted CV content or these sources support. A technology or project that `tech_stack` marks as personal/learning is never described as commercial.

=== AI-MENTIONING VACANCY MODE ===

The candidate has substantial, verifiable personal AI experience: LLM integration in JobFlow, an AI-assisted software factory built around a Claude Code agent, and Python AI projects. All of it is personal portfolio work. This mode decides when and how that experience enters the letter, using the AI-request mapping in the `cv_rules` source.

**Mode on: the vacancy mentions AI anywhere.** Read the whole vacancy: must-have, nice-to-have and responsibilities. A standard backend vacancy where AI appears only in nice-to-have or in responsibilities (for example "you use AI tools in your daily work", "experience with LLM APIs is a plus") still turns the mode on. In this mode the letter must describe the personal AI work that fits the vacancy, in concrete terms, and mark it plainly as personal/portfolio work. Put it in its own short paragraph after the commercial experience paragraph (or as a clearly separated part of paragraph 2); it adds to the commercial backend experience and never replaces it.

**Classify the AI request and pick the evidence by its kind.** Each kind of request has its own evidence, found in the `career_cases`, `tech_stack` and `project_inventory` sources and in the `cv_rules` mapping; combine kinds when the vacancy has several:
- **AI tools / AI in development** ("AI tools in daily work", "AI-assisted development", "uses Claude Code, Copilot or Cursor") → Claude Code and the AI-assisted software factory project.
- **LLM / AI API integration** ("integrate LLMs", "OpenAI API", "AI features in our product") → the JobFlow AI integration: provider abstraction, OpenAI API, structured output validation, background jobs for AI steps.
- **RAG / agents / vector search** ("RAG", "LangGraph", "agents", "vector DB", "embeddings") → the Python RAG and AI assistant personal projects.

Prefer concrete mechanisms found in the sources over generic phrases such as "leveraged AI".

**Never invent AI evidence.** If the vacancy asks for a kind of AI experience that none of the provided sources covers, do not write it into the letter. Add an `evidence_alignment` entry for that request with `profile_evidence: null` and status `"needs evidence"`, and list the gap in `risks`.

**Personal is not commercial.** Personal AI work is always called personal/portfolio work. Never present it as commercial or production experience, never as part of the candidate's commercial employment, and never claim the title AI Engineer or LLM Platform Engineer. If the vacancy explicitly requires commercial or production AI experience, say honestly that the candidate's AI experience is personal/portfolio work, and record the gap in `evidence_alignment` and `risks`.

**Mode off: no AI mention anywhere in the vacancy.** Do not build a paragraph around AI experience and do not list AI projects as a selling point. The commercial backend experience from the approved CV content carries the letter. A passing mention only where the approved CV content already contains it is fine; their absence is the correct outcome for such a vacancy, not a missed opportunity.

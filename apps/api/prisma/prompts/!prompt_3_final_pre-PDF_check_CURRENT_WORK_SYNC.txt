## 6. BOP natural public-CV style check

Run a Best Output Practice / natural public-CV wording check before approving PDF creation.

Goal: the final CV must sound like a human candidate describing professional experience, not like internal evidence analysis, prompt output, safety-audit text, or generated-CV feature labels.

Check Headline, Summary, Current Independent Work, EPAM bullets, Factor–IT bullets and CHI wording for the 16 known problematic phrasing patterns:

1. `AI Tooling Projects` in the headline.
2. `adds AI-tooling exposure`.
3. `commercial production evidence` / `EPAM remains the main commercial production evidence`.
4. `continued active software development` when a simpler sentence fits.
5. `structured upskilling`.
6. `evidence-based claim validation` unless the role explicitly values CV/document claim validation.
7. `human-in-the-loop AI workflow concepts`.
8. `artifact traceability` as a CV feature-label dump.
9. `backend HTML-to-PDF export without AI token usage`.
10. `microservice-based Azure serverless architecture`.
11. `maintained/contributed`.
12. `product-information flows`.
13. `Jest-tested services`.
14. `PR-based code review`.
15. `training and volunteer backend services`.
16. `Backend Debugging` in the headline when `Production Debugging` or `Backend Reliability` is clearer.

For every detected phrase, provide:
- problem: why it sounds unnatural;
- replacement: a human-sounding CV sentence;
- scope: exact section/bullet to change.

Recommended replacements:
- `AI Tooling Projects` — remove from headline or move into Current Work as personal project wording.
- `adds AI-tooling exposure` — `Current personal projects include AI-assisted backend tooling...`
- `commercial production evidence` — `recent commercial work at EPAM focused on...`
- `continued active software development` — `After relocating from Ukraine to Germany, continued working on...`
- `structured upskilling` — `continued learning` / `self-directed backend learning`
- `human-in-the-loop AI workflow concepts` — `human review gates`
- `artifact traceability` — omit from CV or use `traceable generated outputs` only when relevant.
- `backend HTML-to-PDF export without AI token usage` — `deterministic backend PDF export`
- `microservice-based Azure serverless architecture` — `Azure serverless environment`
- `maintained/contributed` — `later supported its maintenance with the team`
- `product-information flows` — `backend and BFF flows supporting product information pages`
- `Jest-tested services` — `backend unit testing with Jest`
- `PR-based code review` — `pull request reviews`
- `training and volunteer backend services` — `educational backend services`

Do not approve PDF if Headline, Summary or main Experience bullets still contain internal evidence-audit wording such as `evidence`, `exposure`, `commercial production evidence`, `strongest evidence`, `safe positioning`, `overclaiming boundary`, or slash-draft wording like `maintained/contributed`.

Style recommendations must be concrete and minimal: change only the affected phrase/section, do not rewrite the whole CV if the problem is local.

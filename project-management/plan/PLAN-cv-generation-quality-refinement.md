## Решения по рекомендациям владельца (независимая оценка)

Приняты как предложено (данные поддерживают): F1 вариант A, F2, F4 как наблюдение, F5, F6 минимально, F7, F8 без изменений, ограничение Docker, F10 без механизма, S6 вне набора, отложенная видимость B1, бюджет 17 вызовов и порядок прогонов.

Уточнения, принятые при планировании:

1. **Две задачи — да, без дробления.** Phase 1 нельзя разделить на «Prompt 2» и «Prompt 3»: канон F1 и определение дубля F2 должны одновременно появиться на стороне генерации и проверки. Иначе на `main` появится состояние с противоречием, которое мы устраняем.
2. **F3 и правило ISSUE-278.** Сужение сформулировано как определение области композитной записи CIW, а не как обрезка по релевантности. Откат в ISSUE-278 касался удаления подтверждённых технологий записи. Описание шаблона `prompt2_v6` в `prisma/seed.ts` (стр. 488): пакет из пяти правил ухудшил сравнительную оценку с 86 до 82, «most likely» из-за правила обрезки `tech_stack`, и был откатан целиком; правило «never remove» в `prompt2_v12.txt` (стр. 244) — его наследник. Здесь стеки невыбранных приложений никогда не были доказательствами видимой записи. Исключение — AI-технологии JobFlow, не названные bullets: это прямое решение владельца в пользу правил AI weight/kind.
3. **Устаревшие цитаты шаблона CIW в `master_cv`, `career_cases`, `project_inventory` — не правятся.** Новые версии трёх источников (в одном из них registry) ради цитаты, которая для Prompt 2 уже перекрыта правилом приоритета `cv_rules` §8, — непропорциональный объём. Prompt 3 `cv_rules` не получает, а `career_cases` получает. Риск, что Prompt 3 «восстановит» форму из `career_cases`, закрыт явным каноном и указанием на устаревшую цитату в Prompt 3 и проверяется метрикой `touchesStableIntro` в Phase 2. Если в D будет хоть одна такая правка — отдельная задача.
4. **«product-information flows» в источниках** — новое наблюдение, не в скоупе: экспорт корректен (Prompt 3 исправляет 5/5 по совпадающему `original_text`), исправление потребовало бы четырёх версий источников.
5. **Формат `language` (ISO 639-1)** добавлен в F7 как часть контракта промпта. Он делает критерий AC-B4 по языку однозначным и не меняет схему.

**Уточнения владельца при одобрении (2026-11-25) — приняты:**
- **F3, область JobFlow.** Принято. Прежняя формулировка («`techStack` JobFlow целиком») воспроизводила уровень S1/S2 Baseline B (16 позиций) и не учитывала релевантность. Теперь в строку идут только технологии, которые названы bullets блока или вакансией.

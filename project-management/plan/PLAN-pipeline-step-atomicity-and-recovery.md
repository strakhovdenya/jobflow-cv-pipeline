# Plan: Pipeline Step Atomicity and Recovery (EPIC-29)

**PRD:** `project-management/prd/PRD-pipeline-step-atomicity-and-recovery.md`
**Дата:** 2026-09-26

Фазы 1–5 меняют `apps/api`, фаза 6 — `apps/web`. Тесты каждого изменения — в той же задаче.
Рекомендуется epic base branch `task/ISSUE-<tracking-issue-n>-step-atomicity-base` (ADR-025/ADR-030): до
фазы 3 захват шага существует без атомарного продвижения результата, и `main` в таком промежуточном
состоянии держать не стоит.

## Фазы реализации

### Фаза 1: Захват шага
**Цель:** Пока шаг выполняется, никакое другое действие на workspace не проходит.
**Затрагивает:** apps/api, PostgreSQL (Prisma)
**Задачи:**
- [ ] Поля `activeStep`, `activeStepStartedAt`, `lastStepError` в `ApplicationWorkspace` и миграция; сервис захвата/освобождения CAS-ом с освобождением устаревшего захвата по правилу ADR-038
- [ ] Проверка захвата в постановке AI-шагов, review-гейтах и экспорте (409); `activeStep` и `lastStepError` в `GET /workspaces/:id`
- [ ] e2e на реальных Postgres и Redis: второй шаг, review-гейт и экспорт во время работающего шага получают 409

**Когда готова:** закрывает PRD AC «Пока шаг выполняется, постановка другого AI-шага, review-гейт и
экспорт того же workspace отвечают 409».

### Фаза 2: Версионные файлы артефактов
**Цель:** Каждая версия артефакта хранится в своём файле, каноническое имя — копия последней продвинутой версии.
**Затрагивает:** apps/api, PostgreSQL (Prisma), файловые артефакты (STORAGE_ROOT)
**Задачи:**
- [ ] `ArtifactStorageService`: запись версии в `<canonical>.v<N>.<ext>`, обновление канонической копии только при продвижении; containment в функции-стоке
- [ ] `ArtifactsService`: регистрация версии с её собственным `filePath`; продвижение (latest + каноническая копия) в переданной транзакции
- [ ] Миграция данных: исторические версии с перезаписанным файлом помечаются «содержимое не сохранено»; скачивание такой версии — понятная ошибка
- [ ] Тест: скачивание версии N отдаёт её содержимое и совпадает с `contentHash`

**Когда готова:** закрывает PRD AC «Каждая версия артефакта хранится в своём файле…» и «Миграция
помечает исторические версии с перезаписанным файлом…».

### Фаза 3: Атомарное продвижение результатов AI-шагов
**Цель:** Результат шага становится текущим только вместе со сменой статуса и освобождением захвата.
**Затрагивает:** apps/api
**Задачи:**
- [ ] Prompt 2 (первая генерация и regenerate): выход в версию, продвижение + инвалидация `03_*` (ADR-037) + CAS статуса + освобождение захвата в одной транзакции; невалидный вывод сохраняется отдельно и не становится latest
- [ ] Prompt 3 и Prompt 5 по той же схеме
- [ ] skip-reason и cover letter по той же схеме
- [ ] Тест на каждый шаг: проигранный CAS или ошибка после AI не меняют latest, каноническую копию, `03_*` и статус

**Когда готова:** закрывает PRD AC «Шаг, проигравший CAS статуса или упавший после вызова AI, не
меняет…» и «Невалидный вывод regenerate не меняет md и json черновика…».

### Фаза 4: Откат статусов и повтор
**Цель:** Транзиентная ошибка не требует повторять пайплайн с Prompt 1.
**Затрагивает:** apps/api
**Задачи:**
- [ ] Таблица переходов по PRD: экспорт → `paused_before_export`, первая генерация CV остаётся `cv_generation_running`, confirm-skip остаётся `paused_after_analysis`, `analysis_ready → paused_after_analysis`; запись `lastStepError`
- [ ] Повторный Prompt 1 сбрасывает `reviewState` и снимает latest с артефактов шагов 2–5
- [ ] `AiStepsService.enqueue` без гонки при повторном использовании id задачи
- [ ] ADR (захват шага, версии файлов, откат статусов; амендменты ADR-037/038/039); `docs/03_domain_model.md`, `docs/04_architecture.md`, `docs/09_artifact_storage.md`, корневой `CLAUDE.md` (Key Invariants)

**Когда готова:** закрывает PRD AC «Ошибка экспорта возвращает workspace в `paused_before_export`…»,
«Ошибка confirm-skip оставляет `paused_after_analysis`…», «Повторный Prompt 1 сбрасывает
`reviewState`…», «Две параллельные постановки одного шага…» и AC о документации.

### Фаза 5: e2e конкурентности
**Цель:** Гарантии ADR-038/039 и этого эпика проверены на реальной БД, а не на моках.
**Затрагивает:** apps/api (тесты)
**Задачи:**
- [ ] e2e: два `PromptRun.create` одного шага — один успех, один 409; два CAS статуса из одного состояния — один победитель
- [ ] e2e: после миграции существующие workspace открываются и экспортируются

**Когда готова:** закрывает PRD AC «e2e на реальной БД: два `PromptRun.create`…» и завершает AC о
миграции.

### Фаза 6: UI повтора
**Цель:** Пользователь видит ошибку шага и может повторить его одной кнопкой.
**Затрагивает:** apps/web
**Задачи:**
- [ ] View-model и main action card показывают `lastStepError` и кнопку повтора шага для статусов из таблицы переходов; кнопки блокируются, пока `activeStep` занят

**Когда готова:** закрывает PRD AC «`apps/web` показывает `lastStepError` и кнопку повтора шага».

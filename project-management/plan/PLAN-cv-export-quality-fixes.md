# Plan: CV Export Quality Fixes (from EPIC-25 first manual parity pass)

**PRD:** `project-management/prd/PRD-cv-export-quality-fixes.md`
**Дата:** 2026-08-24

## Правило выполнения: смена модели перед правкой текста промпта

Применимо к Фазам 3 и 4 (и любой будущей фазе, правящей содержимое `prisma/prompts/*.txt`):
перед тем как вносить непосредственную правку в сам текст промпта (формулировки инструкций,
чеклист-пункты, примеры, любой контент внутри `.txt`-файла промпта) — **остановиться и явно
попросить пользователя переключить модель с Sonnet на Opus**, дождаться подтверждения
переключения, и только после этого делать саму правку текста. Все остальные действия задачи
(чтение issues/докuментации, поиск по коду, git/branch-операции, `prisma/seed.ts`, запуск
tsc/lint/test, работа с GitHub issues и Project) выполняются на Sonnet как обычно — переключение
нужно только на момент самой правки текста промпта, не на всю задачу.

Причина: качество формулировок промпта (насколько точно и without semantic drift переведён/
дополнен инструктивный текст, который затем управляет поведением AI-провайдера) — то место в
этой работе, где имеет смысл более сильная модель; всё остальное — механическая/детерминированная
работа, для которой Sonnet достаточно.
Source: user request, 2026-08-25.

---

Все 6 фаз — apps/api и project-level документация, ни одна не требует apps/web, каждая
независимо тестируема и даёт рабочий результат сама по себе. Формально это подпадает под общий
критерий "их больше двух, каждая независимо тестируема" из инструкции этого скилла (обычно —
сигнал завести epic base branch, ADR-025). Но PRD уже явно рассмотрел этот вопрос и решил **не**
заводить epic base branch — по прецеденту самого EPIC-24 (родительского эпика), все 11 фаз
которого мержились последовательными PR прямо в `main` без общей base-ветки. Это решение PRD
здесь не переопределяется: каждая фаза заводится и мержится как отдельный PR в `main`, тем же
методом, что и Фазы 1–11 EPIC-24 (ISSUE-247–250).

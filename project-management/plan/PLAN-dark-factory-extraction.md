# Plan: Dark Factory Extraction (EPIC-28)

**PRD:** `project-management/prd/PRD-dark-factory-extraction.md`
**Дата:** 2026-09-26 (обновлено 2026-10-11: слой контекста проекта, доставка пакета Claude Code, golden eval — ISSUE-641; 2026-10-12: окружение разработки фабрики, три слоя скиллов и агентов — ISSUE-652)

Старт — после закрытия EPIC-27 (решение владельца, PRD «Открытые вопросы» п. 6). Фазы 0–5 идут в
новом репозитории `strakhovdenya/dark-factory`, фаза 6 — в jobflow, фаза 7 — в cards. Ни одна фаза не

разработки фабрики не используется (PRD «Открытые вопросы» п. 9).

## Фазы реализации

### Фаза 0: Окружение разработки фабрики (бутстрап)
**Цель:** Сессия Claude Code в репозитории фабрики с первого коммита работает по правилам фабрики:
свой `CLAUDE.md`, свои скиллы и агенты, JS-метаскиллы, lint/typecheck — и не путает их с
исходниками пакета, который уходит проектам.
**Затрагивает:** репозиторий `dark-factory` (`CLAUDE.md`, `.claude/skills/`, `.claude/agents/`,
`.claude/settings.json`, `.gitignore`, раскладка каталогов)
**Задачи:**
- [ ] Раскладка каталогов: исходники пакета (скиллы, агенты, хуки) — в каталоге пакета вне `.claude/`; `.claude/` фабрики и её профиль не входят в `files` `package.json`
- [ ] Корневой `CLAUDE.md` фабрики: назначение, раскладка, команды тестов, инварианты ядра PRD, Windows + Linux, тесты без сети и реального AI, правила добавления элемента (PRD п. 16), порядок «правка → релиз → смена тега в фабрике», восстановление при сломанном закреплённом релизе (откат тега через npm/git, не через Write/Edit), процесс задач фабрики (issue по контракту, шаблон веток, `issues`/`task-lifecycle`)
- [ ] Собственные скиллы и агенты фабрики в `.claude/` (состав решается в задаче; примеры PRD п. 20: добавление элемента, выпуск релиза, поиск литералов проектов в ядре, прогон на двух фикстурных профилях)
- [ ] JS-метаскиллы ставятся в фабрику напрямую (как `setup-metaskills.js` jobflow) до первого релиза; lint/typecheck хуки в `.claude/settings.json`

**Когда готова:** закрывает PRD AC «До первого релиза (бутстрап) в репозитории фабрики есть
корневой `CLAUDE.md`, собственные скиллы и агенты фабрики в `.claude/`, установленные
JS-метаскиллы и записи хуков lint/typecheck…»; начинает AC «В `.claude/skills/` и
`.claude/agents/` фабрики есть собственные скиллы и агенты фабрики…», который завершается в
Фазе 4 (проверка, что они не попадают в проект).

**Задачи:**

**Цель:** Верификатор EPIC-27 работает из репозитория фабрики как reusable workflow, настраивается
trusted-конфигами проекта и принимает новые проверки как модули.
**Затрагивает:** репозиторий `dark-factory` (скрипты верификатора, промпт, схема, reusable workflow,
контракт issue)
**Задачи:**
- [ ] Перенос скриптов, промпта и схемы верификатора EPIC-27 в фабрику; движок golden eval (в том виде, в каком он есть к старту: с мутациями EPIC-31 #570/#571 или без них) читает каталог эталонных кейсов из профиля, формат кейса общий; работа EPIC-31 в фазу не входит; детерминированные проверки — модули с общим интерфейсом «входы → причины FAIL»
- [ ] Reusable workflow (`workflow_call`) и пример обёртки на `workflow_run`; скрипты берутся из checkout фабрики по тегу с default-ветки проекта
- [ ] Контракт issue: ядро + overlay проекта, overlay не может убрать базовые секции и запрещённые формулировки; линтер принимает русские и английские имена секций
- [ ] Тесты верификатора на двух фикстурных профилях и тест фиктивной проверки, подключённой только регистрацией и профилем

**Когда готова:** закрывает PRD AC «Верификатор подключается к проекту обёрткой на `workflow_run`,
вызывающей reusable workflow фабрики по SHA; скрипты верификатора берутся из checkout фабрики, не из
проекта» и «Контракт issue: overlay проекта, удаляющий базовую секцию или запрещённую формулировку,
отклоняется линтером» и «Движок golden eval в ядре читает каталог эталонных кейсов из профиля…»; даёт часть AC о двух профилях, о фиктивной проверке и о русских/английских
именах секций.

### Фаза 3: Ядро Ralph
**Цель:** Одна версия Ralph вместо двух разошедшихся копий, собранная как конвейер шагов и
настраиваемая профилем.
**Затрагивает:** репозиторий `dark-factory` (контроллер Ralph, промпты, парсинг, работа с клоном)
**Задачи:**
- [ ] Слияние Ralph из jobflow и cards: общая часть, различия из таблицы PRD — параметры профиля; перенос исправлений, сделанных только в одной версии (`hasCodeChanges`, `missingRequiredSkills`); `missingRequiredSkills` читает таблицу «путь → скиллы» из профиля (тот же источник, что у skill gate хука), промпт агента перечисляет файлы правил проекта из профиля
- [ ] Конвейер шагов (реализация → self-review → code-review → финальная проверка): у шага свои промпт, права агента, формат вердикта и бюджет попыток; профиль выбирает включённые шаги
- [ ] Тест контроллера с подменённым агентом на двух фикстурных профилях и тест фиктивного шага, подключённого только регистрацией и профилем
- [ ] Перенос песочницы из jobflow (#506): Docker-контейнер для агента, установки зависимостей и финального гейта, прокси с allowlist хостов, авторизация `claude` только явным ключом. Модуль `sandbox.js` переносится как есть, проектные значения (образ, список хостов) становятся параметрами профиля; Ralph из cards получает песочницу через общее ядро

**Когда готова:** закрывает PRD AC «Тест ядра прогоняет Ralph-контроллер (с подменённым агентом) и
верификатор (с фикстурным отчётом модели) на двух профилях…» и «Тест ядра добавляет фиктивный шаг
Ralph и фиктивную проверку верификатора только через регистрацию и профиль…» и «Промпт агента Ralph перечисляет файлы правил проекта из профиля»; даёт часть AC «Skill gate хука и промпт Ralph на одном профиле требуют… один и тот же набор скиллов».

### Фаза 4: Пакет скиллов, агентов и хуков
**Цель:** Скиллы, агенты и хуки фабрики на английском раскладываются в проект setup-скриптом и
берут проектные значения из профиля.
**Затрагивает:** репозиторий `dark-factory` (скиллы `prd`/`plan`/`issues`/`task-lifecycle`/
`epic-discovery`, агенты, хуки, setup-скрипт)
**Задачи:**
- [ ] Базовый набор скиллов и агентов пакета (PRD п. 20): состав (скиллы процесса, базовые JS-метаскиллы, базовые агенты) и базовые записи таблицы «путь → скиллы»; базовые скиллы и агенты берут проектные значения из профиля (например, команды проверки для `verify`), а не из своего текста; итоговая таблица = базовые записи + записи профиля (тест на двух фикстурных профилях: `.ts` требует базовые JS-метаскиллы, путь из записи профиля — ещё и её скиллы)
- [ ] Setup-скрипт на `postinstall`: копирование базового набора скиллов и агентов пакета и дополнительных метаскиллов из профиля в `.claude/skills/` и `.claude/agents/` (каждая копия перечислена в `.gitignore` по имени), список установленных копий и удаление устаревших, остановка с сообщением при конфликте имени с отслеживаемым файлом, работа в клонах Ralph и в CI; отслеживаемые файлы проекта, в том числе `.claude/settings.json`, не меняются; совпадение имени своего скилла или агента проекта с базовым — конфликт с сообщением; скиллы и агенты из `.claude/` фабрики в проект не попадают (тесты на временном репозитории)
- [ ] Скиллы и агенты без проектных значений (пути документов, ID Project, ADR — из профиля); overlay секций шаблонов PRD/плана/issue из профиля, удаление базовой секции отклоняется (тест)
- [ ] Перевод скиллов, агентов, промптов Ralph и README фабрики на английский
- [ ] Хуки ядра, параметризованные профилем: closure gate (`git commit`/`git push` и тело issue для `gh issue create|edit` и `mcp__github__issue_write`), skill gate по таблице «путь → скиллы» профиля, skill marker (PostToolUse `Skill`), lint/typecheck с командами по путям; подключение в `.claude/settings.json` проекта в shell form `node "$CLAUDE_PROJECT_DIR/node_modules/dark-factory/hooks/..."` (exec form — только после теста раскрытия `${CLAUDE_PROJECT_DIR}` в `args`); хуки-гейты fail closed: сбой скрипта или отсутствие пакета дают код 2, lint/typecheck не блокируют; профиль ищется от `CLAUDE_PROJECT_DIR`; тесты «`echo git commit` не перехватывается», «хук и Ralph требуют для пути одни скиллы», «хук работает из корня временной рабочей копии», «без профиля хук блокирует с сообщением»

**Когда готова:** закрывает PRD AC «Скиллы, агенты, промпты Ralph и README фабрики написаны
по-английски; линтер принимает и русские, и английские имена секций контракта (тест)», AC о базовом
наборе скиллов и агентов, об итоговой таблице «путь → скиллы» и о собственных скиллах и агентах
фабрики (в проект не попадают) и
«В репозитории фабрики есть ядро верификатора, ядро Ralph и пакет скиллов/агентов/хуков; тесты ядра
зелёные в CI фабрики на Linux и Windows», а также AC об overlay шаблонов, о setup-скрипте, о поиске профиля от `CLAUDE_PROJECT_DIR` и завершает AC «Skill gate хука и промпт Ralph… один и тот же набор скиллов».

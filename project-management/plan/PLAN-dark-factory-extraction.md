# Plan: Dark Factory Extraction (EPIC-28)

**PRD:** `project-management/prd/PRD-dark-factory-extraction.md`
**Дата:** 2026-09-26

Старт — после закрытия EPIC-27 (решение владельца, PRD «Открытые вопросы» п. 6). Фазы 1–5 идут в
новом репозитории `strakhovdenya/dark-factory`, фаза 6 — в jobflow, фаза 7 — в cards. Ни одна фаза не
затрагивает `apps/*`, PostgreSQL/Prisma или `STORAGE_ROOT`. Тесты каждого модуля — в той же задаче,
что его создаёт.

## Фазы реализации

### Фаза 1: Каркас фабрики и профиль проекта
**Цель:** Появляется репозиторий фабрики с CI на Linux и Windows, схемой профиля проекта и
автоматическим запретом литералов проекта в коде ядра — основа, на которую ложатся все остальные
фазы.
**Затрагивает:** репозиторий `dark-factory` (структура пакета, CI, схема профиля); профили jobflow и
cards как фикстуры
**Задачи:**
- [ ] Каркас репозитория `dark-factory`: npm-пакет, релизы по тегам, CHANGELOG, CI на Linux и Windows
- [ ] JSON-схема профиля проекта со всеми точками различия из таблицы «Контекст» PRD и валидатор с сообщениями по полю
- [ ] Фикстурные профили «монорепо» и «один пакет» и профили jobflow и cards с их текущими значениями
- [ ] Тест в CI фабрики: поиск литералов проектов в коде ядра (список из PRD) вне фикстур, примеров профилей и метаданных пакета

**Когда готова:** закрывает PRD AC «JSON-схема профиля проекта описывает каждую точку различия из
таблицы «Контекст»; невалидный профиль отклоняется с сообщением, называющим поле» и «Поиск по коду
ядра не находит `apps/api`, `apps/web`, `jobflow`, `cards`, `supabase`, `prisma` вне фикстур…»;
начинает AC «…тесты ядра зелёные в CI фабрики на Linux и Windows».

### Фаза 2: Ядро верификатора
**Цель:** Верификатор EPIC-27 работает из репозитория фабрики как reusable workflow, настраивается
trusted-конфигами проекта и принимает новые проверки как модули.
**Затрагивает:** репозиторий `dark-factory` (скрипты верификатора, промпт, схема, reusable workflow,
контракт issue)
**Задачи:**
- [ ] Перенос скриптов, промпта и схемы верификатора EPIC-27 в фабрику; детерминированные проверки — модули с общим интерфейсом «входы → причины FAIL»
- [ ] Reusable workflow (`workflow_call`) и пример обёртки на `workflow_run`; скрипты берутся из checkout фабрики по тегу с default-ветки проекта
- [ ] Контракт issue: ядро + overlay проекта, overlay не может убрать базовые секции и запрещённые формулировки; линтер принимает русские и английские имена секций
- [ ] Тесты верификатора на двух фикстурных профилях и тест фиктивной проверки, подключённой только регистрацией и профилем

**Когда готова:** закрывает PRD AC «Верификатор подключается к проекту обёрткой на `workflow_run`,
вызывающей reusable workflow фабрики по SHA; скрипты верификатора берутся из checkout фабрики, не из
проекта» и «Контракт issue: overlay проекта, удаляющий базовую секцию или запрещённую формулировку,
отклоняется линтером»; даёт часть AC о двух профилях, о фиктивной проверке и о русских/английских
именах секций.

### Фаза 3: Ядро Ralph
**Цель:** Одна версия Ralph вместо двух разошедшихся копий, собранная как конвейер шагов и
настраиваемая профилем.
**Затрагивает:** репозиторий `dark-factory` (контроллер Ralph, промпты, парсинг, работа с клоном)
**Задачи:**
- [ ] Слияние Ralph из jobflow и cards: общая часть, различия из таблицы PRD — параметры профиля; перенос исправлений, сделанных только в одной версии (`hasCodeChanges`, `missingRequiredSkills`)
- [ ] Конвейер шагов (реализация → self-review → code-review → финальная проверка): у шага свои промпт, права агента, формат вердикта и бюджет попыток; профиль выбирает включённые шаги
- [ ] Тест контроллера с подменённым агентом на двух фикстурных профилях и тест фиктивного шага, подключённого только регистрацией и профилем

**Когда готова:** закрывает PRD AC «Тест ядра прогоняет Ralph-контроллер (с подменённым агентом) и
верификатор (с фикстурным отчётом модели) на двух профилях…» и «Тест ядра добавляет фиктивный шаг
Ralph и фиктивную проверку верификатора только через регистрацию и профиль…».

### Фаза 4: Пакет скиллов, агентов и хуков
**Цель:** Скиллы, агенты и хуки фабрики на английском раскладываются в проект setup-скриптом и
берут проектные значения из профиля.
**Затрагивает:** репозиторий `dark-factory` (скиллы `prd`/`plan`/`issues`/`task-lifecycle`/
`epic-discovery`, агенты, хуки, setup-скрипт)
**Задачи:**
- [ ] Setup-скрипт на `postinstall`: раскладка скиллов, агентов и хуков в `.claude/` проекта, работа в клонах Ralph и в CI
- [ ] Скиллы и агенты без проектных значений (пути документов, ID Project, ADR — из профиля)
- [ ] Перевод скиллов, агентов, промптов Ralph и README фабрики на английский
- [ ] Хуки gate/lint/typecheck из ядра, параметризованные профилем; тест «`echo git commit` не перехватывается»

**Когда готова:** закрывает PRD AC «Скиллы, агенты, промпты Ralph и README фабрики написаны
по-английски; линтер принимает и русские, и английские имена секций контракта (тест)» и
«В репозитории фабрики есть ядро верификатора, ядро Ralph и пакет скиллов/агентов/хуков; тесты ядра
зелёные в CI фабрики на Linux и Windows».

### Фаза 5: factory doctor и документация
**Цель:** Подключение проекта к фабрике проверяется одной командой и описано так, что его можно
повторить без автора.
**Затрагивает:** репозиторий `dark-factory` (`factory doctor`, README, руководства, CHANGELOG)
**Задачи:**
- [ ] `factory doctor`: проверка профиля, trusted-конфигов, лейблов, секрета `OPENAI_API_KEY`, переменной `VERIFIER_MODEL`, обёртки верификатора, с тестами
- [ ] Руководство: подключение проекта, обновление версии, добавление точки настройки
- [ ] Правила добавления нового элемента фабрики: схема профиля, выключен по умолчанию, тесты на двух профилях, эталонный набор, CHANGELOG

**Когда готова:** закрывает PRD AC «`factory doctor` сообщает об отсутствующих…» и «Документация
фабрики описывает правила добавления нового элемента…»; даёт документацию для AC «Документация
фабрики описывает подключение проекта, обновление версии и добавление новой точки настройки…».

### Фаза 6: Перевод jobflow на пакет
**Цель:** jobflow работает на фабрике из пакета с тем же поведением, что до перевода.
**Затрагивает:** jobflow: `.claude/`, `scripts/`, `.github/verifier/`, `.github/workflows/`,
`package.json`, `CLAUDE.md`, `docs/12_ai_software_factory.md`, `project-management/DECISIONS.md`
**Задачи:**
- [ ] Подключение пакета по тегу, профиль jobflow, trusted-конфиги; обёртка верификатора на reusable workflow
- [ ] Удаление локальных копий скиллов, хуков, Ralph и скриптов верификатора; ссылки на документацию фабрики в `CLAUDE.md` и `docs/12_ai_software_factory.md`; ADR о выносе
- [ ] Прогон эталонного набора PR jobflow до и после перевода с совпадающими вердиктами

**Когда готова:** закрывает PRD AC «jobflow переведён на пакет: локальные копии… удалены или
заменены ссылкой на пакет; эталонный набор PR jobflow даёт те же вердикты, что до перевода»; даёт
ссылку jobflow для AC о документации.

### Фаза 7: Подключение cards
**Цель:** cards получает всю фабрику из пакета, включая верификатор в режиме advisory и CodeQL.
**Затрагивает:** cards: `.claude/`, `scripts/`, `.github/verifier/`, `.github/workflows/`,
`package.json`, `CLAUDE.md`, `project-management/DECISIONS.md`
**Задачи:**
- [ ] Подключение пакета по тегу, профиль cards с параметрами из таблицы PRD, trusted-конфиги; удаление локальных копий Ralph, скиллов и хуков
- [ ] Верификатор в режиме advisory через обёртку на reusable workflow
- [ ] CodeQL в CI cards и его включение в trusted-список обязательных проверок cards
- [ ] Эталонный набор cards из минимум 3 PR с ожидаемыми вердиктами; ссылка на документацию фабрики в `CLAUDE.md` cards; ADR о подключении

**Когда готова:** закрывает PRD AC «cards подключён: профиль с параметрами из таблицы «Контекст»,
верификатор, скиллы и Ralph из пакета; `echo git commit` в Bash не перехватывается хуком cards
(тест)», «Эталонный набор cards содержит минимум 3 PR с ожидаемыми вердиктами», «CI cards содержит
CodeQL, и он входит в trusted-список обязательных проверок cards» и завершает AC «Документация
фабрики описывает подключение проекта… в обоих проектах есть ссылка на неё».

Epic base branch не рекомендуется: фазы 1–5 идут в отдельном репозитории `dark-factory`, фазы 6 и 7 —
по одному PR в jobflow и cards соответственно.

# PRD: CV Export Quality Fixes (from EPIC-25 first manual parity pass)

**Дата**: 2026-08-24
**Статус**: Draft
**Затрагиваемое приложение**: apps/api
**Связанный issue/backlog-пункт**: новая фича — ещё не заведена как issue. Соответствует
**EPIC-25 — Manual Parity Testing / Regression QA** (`docs/05_epics.md`, Phase 18 в
`docs/06_roadmap.md`), которая до сих пор не заведена ни одним GitHub Issue/milestone (EPIC-24's
milestones идут только до "Фаза 11"). **Решено**: заводится как новый набор milestones
"EPIC-25 · Фаза N: ..." (по аналогии с EPIC-24), без epic base branch (ADR-025) — по прецеденту
самого EPIC-24, все 11 фаз которого мержились прямо в `main` последовательными PR.

## Цель

Устранить конкретные дефекты качества CV, найденные при первом реальном (не golden-dataset)
прогоне пайплайна после ISSUE-249/250 — часть из них ломает содержимое каждого сгенерированного
резюме (не только этого кейса), часть — архитектурный пробел, из-за которого Prompt 3 не может
подстраховать эти дефекты в принципе, часть — формулировки промптов, которые пайплайн вынужден
исправлять на лету при каждом прогоне вместо исправления один раз в источнике.

## Контекст и согласованность с проектом

Источник: `project-management/analysis-galaktica-real-world-cv-quality.md` — разбор реального
экспорта (`2026_08_24_Galaktica_Middle_Full_Stack_Developer`), каждая находка подтверждена прямым
чтением кода/данных этого прогона, не предположением.

Затрагивает Prompt 2 (`prisma/prompts/prompt2_v4.txt`), Prompt 3 (`prisma/prompts/prompt3_v4.txt`),
`document-export/` (`prompt2-to-cv-content.mapper.ts`, `candidate-profile.config.ts`) и
`pipeline/prompt3/prompt3-input-builder.service.ts`. Canonical-артефакты, которые это затрагивает:
`02_targeted_cv_content.md/json`, `03_pre_pdf_check.md/json`, `04_cv_export.html/pdf`.

Связанные ADR: ADR-021 (schema-файлы называются по canonical-артефакту, не по номеру шага — не
нарушается этой фичей), ADR-026 (Prompt 3 — mandatory-but-skippable gate, verdict не блокирует
экспорт — не нарушается), ADR-031 (`export_blocked` advisory-only — не нарушается), ADR-030
(GitHub Issues — источник правды для задач).

## Пользовательские сценарии

- Пользователь генерирует CV через реальный пайплайн (`AI_PROVIDER=openai`) для любой вакансии ->
  получает PDF с реальным образованием (не `Placeholder University`), честным уровнем английского,
  без утёкших внутренних заметок, с непустой секцией Certifications и без дублирования одного и
  того же проекта в двух разделах.
- Пользователь пытается экспортировать CV, пока `candidate-profile.config.ts` содержит забытый
  placeholder (например, после будущего редактирования профиля) -> экспорт отклоняется с понятной
  ошибкой вместо того, чтобы тихо отправить PDF с fabricated-данными.

## Ключевые инварианты

- **Anti-Overclaiming Rules** (root CLAUDE.md) прямо применимы к пункту 2: `candidate-profile.config.ts`
  сейчас нарушает базовую честность CV (`Placeholder University`, "Professional working
  proficiency" вместо подтверждённого B1/B1+) — это не overclaiming в смысле придуманного опыта, но
  тот же принцип "CV must not misrepresent the candidate" применяется.
- **Prompt Pipeline Rules**: Prompt 3 остаётся mandatory-but-skippable gate (ADR-026), его verdict
  остаётся advisory-only (ADR-031) — новая детерминированная проверка (пункт 3) не расширяет и не
  подменяет собой Prompt 3, а действует как отдельный, независимый guard на пути экспорта. Нужно
  явно решить в самой задаче, на каком именно шаге он выполняется (`run-pre-pdf-check`,
  `export-cv`, или оба) и является ли он блокирующим (в отличие от advisory-only Prompt 3
  verdict) — этот guard проверяет статические, заведомо неверные данные (placeholder-маркеры), а
  не AI-суждение, поэтому блокирующее поведение здесь не противоречит ADR-026/031, которые
  специально писались про AI-verdict, не про детерминированную валидацию.
- **AI Provider Rules**: новая проверка — не AI-check, не требует моков AI provider в тестах вовсе.
- **"Never silently overwrite a template version"**: любые правки `prompt2_v4.txt`/`prompt3_v4.txt`
  идут как новые версии (`prompt2_v5.txt`/`prompt3_v5.txt`), предыдущие остаются неактивными, не
  перезаписываются — установившаяся дисциплина этого проекта (см. ISSUE-249/250).
- **Module boundary rules (ADR-017)**: пункт 1 и 2 — правки внутри уже существующих
  `document-export/` файлов, новых модулей не создают.

## Технические ограничения

- Реальные прогоны (для проверки правок 4/5) требуют `AI_PROVIDER=openai` и настоящий API key —
  тратят токены; должны выполняться так же аккуратно, как в ISSUE-249/250 (изолированный
  порт/окружение, возврат на `AI_PROVIDER=fake` по завершении).
- Пункт 3 реализуется как детерминированная проверка (архитектурное решение согласовано при
  обсуждении этого PRD) — деталь того, на каком именно шаге пайплайна она включается и блокирует
  ли она (см. Ключевые инварианты), остаётся на усмотрение самой задачи (issue).

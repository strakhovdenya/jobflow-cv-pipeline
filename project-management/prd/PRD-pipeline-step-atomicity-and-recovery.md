# PRD: Pipeline Step Atomicity and Recovery (EPIC-29)

**Дата**: 2026-09-26
**Статус**: Draft
**Затрагиваемое приложение**: оба (`apps/api` — основное; `apps/web` — кнопка повтора и сообщение об ошибке)
**Связанный issue/backlog-пункт**: поглощает #307 («failed is a dead end»). Источник — аудит 2026-09-24
(`project-management/audit-2026-09-24/TRIAGE.md`), находки P1-002, P1-003, P1-006, P1-008, P1-009,
P1-010, P2-010, P2-011, P3-010.

## Цель

Сделать каждый шаг пайплайна атомарным и восстановимым: пока шаг работает, другие шаги и действия
человека на этом workspace не могут изменить его состояние; результат шага становится «текущим»
только вместе со сменой статуса; транзиентная ошибка не требует повторять весь пайплайн с Prompt 1.

## Контекст и согласованность с проектом

Проверено на `main` `6df932b`:
- **Одновременные разные шаги (P1-002).** ADR-038 сделал запись статуса compare-and-set, но заранее
  захватывают workspace только Prompt 1 (`analysis_running`) и экспорт (`export_running`). Prompt 2
  (включая regenerate), Prompt 3, Prompt 5, skip-reason и cover letter читают статус, минуты ждут
  OpenAI, перезаписывают канонические файлы, регистрируют их как `isLatest`, завершают `PromptRun` и
  только потом делают CAS статуса. Проигранный CAS ничего не откатывает. Дедупликация в очереди
  (`AiStepsService`, id `<step>-<workspaceId>`) защищает только от второго запуска того же шага.
  Итог: при параллельных regenerate и pre-PDF check неотревьюенный черновик может стать
  экспортируемым, или экспорт применит к новому черновику исправления Prompt 3 от старого (ровно то,
  что запрещает ADR-037).
- **Тупик `failed` (P1-003, #307).** `failed → analysis_running` — единственный выход
  (`workspace-status.service.ts`). Сбой первой генерации CV или экспорта заставляет заново платить
  за Prompt 1, Prompt 2 и повторять ревью; в `apps/web` для `failed` нет кнопок.
- **Версии артефактов (P1-006, P2-010, P2-011).** Все версии `GeneratedArtifact` одного типа
  указывают на один канонический файл, который каждый раз перезаписывается; старые версии отдают
  новые байты, `contentHash` не совпадает. Упавший regenerate перезаписывает `02_…md` невалидным
  выводом и регистрирует его latest, а `02_…json` остаётся прежним.
- **Мелкие дефекты восстановления.** P1-008: упавший confirm-skip оставляет `analysis_ready`, откуда
  доступен только Skip. P1-009: повторный Prompt 1 из `failed` не сбрасывает `reviewState` и
  оставляет latest-артефакты предыдущего цикла. P1-010: гонка «проверить → удалить → добавить» в
  `AiStepsService.enqueue` при повторном использовании id задачи.
- **Тесты (P3-010).** Гарантии конкурентности проверяются только на моках; частичный уникальный индекс
  `PromptRun` и CAS статуса на реальной БД не тестируются.

Затрагиваемые canonical-артефакты: `01_*`, `02_*`, `03_*`, `04_cv_export*`, `05_*`, `cover_letter.*`
(способ хранения версий), без изменения их канонических имён (ADR-006).

Связанные ADR: ADR-006 (канонические имена), ADR-026 (гейт pre-PDF), ADR-037 (инвалидация `03_*`),
ADR-038 (CAS статуса, один активный `PromptRun`), ADR-039 (атомарная регистрация артефактов),
ADR-040 (фоновые шаги).

## Зависимости

Явных зависимостей не найдено: все нужные механизмы (CAS статуса, блокировка строки workspace при
регистрации, частичные индексы) уже на `main`. Пересечение по файлам с #406 (обработка `failed`/
`stalled` задач worker'а) — сливать по очереди.

## Пользовательские сценарии

- Пользователь запускает regenerate и во второй вкладке жмёт «Run pre-PDF check» → второй запрос
  получает 409 «шаг уже выполняется», состояние workspace не меняется.
- Экспорт падает из-за транзиентной ошибки Chromium → workspace возвращается в
  `paused_before_export` с текстом ошибки и кнопкой «Повторить», повтор не требует Prompt 1.
- Первая генерация CV падает из-за таймаута OpenAI → workspace возвращается в статус, из которого
  генерация стартовала, с кнопкой «Повторить».
- Regenerate вернул невалидный JSON → черновик, который видит человек (md и json), не меняется.
- Пользователь скачивает старую версию артефакта → получает именно её содержимое.

## В скоупе

1. **Захват workspace шагом.** Поле `ApplicationWorkspace.activeStep` (nullable) и
   `activeStepStartedAt`; захват CAS-ом до вызова AI; освобождение в той же транзакции, что смена
   статуса и продвижение результатов; устаревший захват освобождается по тому же правилу времени,
   что `PromptRun` (ADR-038).
2. **Проверка захвата во всех входах**: постановка AI-шагов, review-гейты, экспорт — 409, пока шаг
   занят.
3. **Продвижение результата вместе со статусом.** Шаг пишет выход в версионный файл; регистрация
   latest, обновление канонической копии, инвалидация `03_*` (ADR-037) и CAS статуса — в одной
   транзакции; при проигранном CAS или ошибке ничего из этого не применяется.
4. **Файл на версию.** `<canonical-name>.v<N>.<ext>` хранится навсегда; каноническое имя — копия
   последней продвинутой версии; скачивание версии отдаёт её собственный файл.
5. **Невалидный вывод модели** сохраняется отдельно (для диагностики) и не становится latest.
6. **Откат к входному статусу при ошибке** для первой генерации CV, экспорта и остальных шагов;
   `failed` остаётся только для Prompt 1.
7. **Сообщение об ошибке и повтор в UI**: последняя ошибка шага видна на workspace, кнопка повтора
   на соответствующем шаге.
8. **P1-008**: переход `analysis_ready → paused_after_analysis` (или откат confirm-skip к
   `paused_after_analysis`).
9. **P1-009**: повторный Prompt 1 сбрасывает `reviewState` и снимает latest с артефактов следующих
   шагов.
10. **P1-010**: постановка задачи без гонки при повторном использовании id (удаление завершённой
    задачи только атомарно по её состоянию; «locked» → 409).
11. **e2e-тесты конкурентности на реальных Postgres и Redis** (P3-010): два шага одного workspace,
    два CAS статуса, два `PromptRun.create`.
12. **Миграция существующих данных**: для каждой текущей версии артефакта, чей файл уже перезаписан,
    версия помечается как «содержимое не сохранено» вместо ложного пути.

## Не в скоупе

- Вынос worker'а в отдельный процесс (P3-014) — отдельное решение.
- Политика повторов провайдера OpenAI — #496.
- Корректное завершение процесса и освобождение `PromptRun` зависших задач — #406.
- Новые шаги пайплайна и изменения промптов.

## Влияние на state machine

Новые переходы (сверх текущих `TRANSITIONS`), все через `WorkspaceStatusService.transition()`
(ADR-038):

| Action | Precondition | Status after | Примечание |
|---|---|---|---|
| Ошибка первой генерации CV | `cv_generation_running` | `cv_generation_running` | статус не меняется, `activeStep` освобождается, ошибка записывается; повтор — тот же шаг |
| Ошибка экспорта | `export_running` | `paused_before_export` | вместо `failed` |
| Ошибка confirm-skip | `paused_after_analysis` | `paused_after_analysis` | вместо `analysis_ready` (P1-008) |
| Повтор из `analysis_ready` (legacy) | `analysis_ready` | `paused_after_analysis` | для уже застрявших workspace |
| Ошибка Prompt 1 | `analysis_running` | `failed` | без изменений |
| Ошибка остальных шагов (regenerate, Prompt 3/5, cover letter) | любой | тот же | без изменений (как сейчас), плюс освобождение `activeStep` |

Итоговая таблица переходов фиксируется в issue фазы state machine и в ADR; при противоречии с этой
таблицей — вопрос владельцу, а не молчаливое согласование.

## Влияние на модель данных

- `ApplicationWorkspace`: `activeStep` (nullable enum шага), `activeStepStartedAt`, `lastStepError`
  (текст), миграция.
- `GeneratedArtifact`: `filePath` каждой версии указывает на свой файл; флаг «содержимое не
  сохранено» для исторических версий (миграция данных).
- Физические файлы остаются в `STORAGE_ROOT` (ADR-002); канонические имена не меняются (ADR-006).

## API-поверхность

- Все эндпоинты постановки AI-шагов, review-гейтов и экспорта отвечают 409 при занятом `activeStep`.
- `GET /workspaces/:id` возвращает `activeStep` и `lastStepError`.
- Эндпоинт повтора не нужен: повтор — это повторный вызов того же шага из того же статуса.
- Изменённые ответы — с `@ApiProperty` (ADR-019).

## Ключевые инварианты

- **Resolved decision (2026-09-26):** захват через поле `activeStep` и CAS; отвергнуты: новые
  `*_running` статусы (разрастание машины состояний), ограничение только в BullMQ (не закрывает
  синхронные review-гейты и экспорт).
- **Resolved decision (2026-09-26):** файл на версию + каноническая копия; отвергнуто «только latest,
  temp+rename» (нет истории содержимого).
- **Resolved decision (2026-09-26):** откат к входному статусу шага; `failed` только для Prompt 1;
  отвергнуты отдельные `*_failed` статусы.
- Любая запись статуса — только через `WorkspaceStatusService.transition()` (ADR-038).
- Захват и освобождение `activeStep` — CAS в БД, не память процесса и не Redis.
- Проигранный CAS или ошибка не оставляют ни одного видимого побочного эффекта: latest-регистрация,
  каноническая копия, удаление `03_*` и статус меняются вместе или не меняются.
- Файлы — только внутри `STORAGE_ROOT`, проверка containment в функции-стоке (корневой `CLAUDE.md`).
- Экспорт по-прежнему не создаёт `AiRun` (ADR-012).
- Существующие workspace после миграции продолжают работать без ручной правки БД.

## Технические ограничения

- AI-вызов не может быть внутри транзакции БД (минуты); транзакция охватывает только продвижение
  результата и смену статуса.
- Частичные индексы и CAS проверяются e2e на реальной Postgres (CI `Test (e2e)`).
- Unit-тесты без реального AI.

## Критерии готовности (Acceptance Criteria)

- [ ] Пока шаг выполняется, постановка другого AI-шага, review-гейт и экспорт того же workspace
      отвечают 409 (e2e на реальных Postgres и Redis).
- [ ] Шаг, проигравший CAS статуса или упавший после вызова AI, не меняет latest-артефакты,
      каноническую копию, `03_*` и статус (unit-тест на каждый AI-шаг).
- [ ] Каждая версия артефакта хранится в своём файле; скачивание версии N отдаёт содержимое версии N
      и совпадает с её `contentHash` (тест).
- [ ] Невалидный вывод regenerate не меняет md и json черновика, видимые человеку (тест).
- [ ] Ошибка экспорта возвращает workspace в `paused_before_export`; ошибка первой генерации CV
      оставляет `cv_generation_running` с освобождённым `activeStep`; повтор проходит без Prompt 1
      (тесты).
- [ ] `apps/web` показывает `lastStepError` и кнопку повтора шага (тест view-model).
- [ ] Ошибка confirm-skip оставляет `paused_after_analysis`; существующие `analysis_ready` можно
      вернуть в `paused_after_analysis` (тест).
- [ ] Повторный Prompt 1 сбрасывает `reviewState` и снимает latest с артефактов шагов 2–5 (тест).
- [ ] Две параллельные постановки одного шага после завершённой задачи не удаляют чужую задачу и не
      дают 500 (e2e).
- [ ] e2e на реальной БД: два `PromptRun.create` одного шага — один успех, один 409; два CAS статуса —
      один победитель.
- [ ] Миграция помечает исторические версии с перезаписанным файлом; после миграции все существующие
      workspace открываются и экспортируются (e2e на данных миграции).
- [ ] ADR о захвате шага, версиях файлов и откате статусов; обновлены `docs/04_architecture.md`,
      `docs/03_domain_model.md` (state machine), корневой `CLAUDE.md` (Key Invariants).

## Test Requirement (набросок)

Unit-тесты сервисов шагов и `WorkspaceStatusService`; e2e на реальных Postgres и Redis для
конкурентности и миграции; тесты view-model `apps/web`; ручная проверка владельцем на реальном
workspace (две вкладки, сбой экспорта).

## Открытые вопросы

Решено с владельцем 2026-09-26:
1. Версии файлов артефактов и невалидные выводы модели хранятся навсегда (объём мал, история и аудит
   важнее). Отвергнуто: хранить последние N.
2. Захват шага снимается только автоматически — по времени (как `PromptRun`, ADR-038) и при падении
   задачи (#406). Кнопки ручного сброса нет. Отвергнуто: кнопка в UI (риск снять захват у ещё
   работающего шага).
